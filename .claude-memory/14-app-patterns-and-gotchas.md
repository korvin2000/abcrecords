## Recurring patterns (learn these once — they repeat everywhere)

- **Lazy + preload singleton.** `LazyX = lazy(loadX)` with a module-level `pending` promise, plus `preloadX = () => void loadX()` fired on hover/focus/click intent. Identical shape in `LazyCodexModal.ts`, `LazyImageViewer.ts`, `LazyAsciiTabViewer.ts`. Copy it for any new heavy overlay — and give it an `ErrorBoundary`, because a failed import is unrecoverable without a reload (see App-wide below).
- **One state value, patched from many controls.** `App` holds one `SearchCriteria`; the search bar, the quick chips and every field in the refinement panel report a `Partial<SearchCriteria>` patch and hold nothing of their own. That is why the chips and the panel can never disagree. Copy this before inventing a second source of truth for a form.
- **Compile once, then loop.** `compile(criteria)` folds terms, parses years and collapses "unset" to `null` **once per criteria change**; the per-entry loop only compares. Same discipline as `buildSearchIndex` (corpus-side) vs `tokenize` (query-side) — split work by *what it depends on*, never by file size.
- **Module-level store + `useSyncExternalStore`.** Work that outlives a component and must happen at most once per (catalogue, language) — today the dossier crawl — lives at module scope with a registry (`factsIndexFor`), a `dispose()`d predecessor, and a **fresh immutable snapshot per notification** so `useMemo` deps behave. Notifications are throttled; completion is not.
- **Tone/variant tables, not conditionals.** `components/herald/tones.ts` maps each tone to its frame class, accent, glyph pair and label key; `CurlFrame`'s `frame:` map does the same for images. A new variant is one row plus its CSS — not an `if` in three components.
- **Light dismiss via `useDismissOnOutside`** (`lib/dismiss.ts`): put the ref on the element owning **both** trigger and panel (anchoring it to the panel alone makes a click on the trigger read as "outside" and re-open in the same gesture). Escape is capture-phase + `stopPropagation` so the innermost layer closes first.
- **Provider + `useX()` overlay.** App-wide overlays (image viewer, ascii-tab viewer) and i18n are React contexts mounted once at root in `main.tsx`. A hook opens them from anywhere; the overlay is mounted `key={src}` under `Suspense`+`AnimatePresence`, so **remount = state reset** (don't "optimize" the key away). `imageViewer.tsx` and `asciiTabViewer.tsx` are near-verbatim twins.
- **Ask the browser, don't assume the format.** `playback.ts` keeps one table of extension → candidate MIME spellings and answers `audioKind()` from `canPlayType`, cached per extension. That is why `.wma` and `.ra` get a download card rather than a play button that errors, and why `.aiff` is playable in Safari but not in Chrome without either being special-cased. Add a format by adding a row; never by widening a regex.
- **Audio singleton + single-active coordinator.** `audio` (from `audio.ts`) is pinged on interactions (`hover/click/pageTurn/open/close`). *Content* playback (mp3/midi/tab-preview/theme) is arbitrated by a module-level `stopActive` in `playback.ts` (`claimPlayback`/`stopAllPlayback`) that keys on the **reference identity** of the stop callback → always pass a stable (`useCallback`) function.
- **Look-ahead scheduler.** Four independent copies (theme + ambient in `audio.ts`, `midi.ts`, `asciiTabPlayback.ts`): `setInterval` (25–40 ms) + a while-loop scheduling notes ≤~0.15 s ahead on the sample-accurate `AudioContext` clock. Position derives from the clock, so suspend = frame-perfect pause.
- **Deterministic-from-seed identity.** `fnv1a(slug/name)` → `mulberry32` → the entry's theme (`themeFromSeed`), accent (`accentFor`), and placeholder portrait (`placeholder.ts`). Same entry ⇒ same look/sound every visit. Reuse `fnv1a`/`accentFor` for any per-entry visual.
- **Motion.** `LazyMotion features={domAnimation} strict` ⇒ use `m.*`, never `motion.*`. framer components gate on `useReducedMotion()`; CSS animations gate on `@media (prefers-reduced-motion)`. (These two are applied inconsistently — see the reduced-motion landmine.)
- **Fail-soft by default.** Parser preserves unknown/malformed content + warns; fetch helpers resolve to `null`; missing metadata → the row is omitted (never an empty label); broken `<img>` → hidden or procedural placeholder. Match this — don't throw in a render path.
- **Type-enforced i18n.** `ru.ts` defines `MsgKey`; the other 9 dicts are `Record<MsgKey,Message>` so drift is a compile error. `DICTS` forces a dict per `Lang`.
- **Styling.** Tailwind v4 utilities + `clsx` for conditionals + semantic classes in `src/styles/*.css` (`.parchment`, `.btn-rpg`, `.bio-article`, `.fx-curl`, footer chrome), which `src/index.css` imports in cascade order. `@/` ⇒ `src/`. **A new component gets a new file plus a line in `index.css`, not an append to whichever file is nearest.**
- **Two-base paths & promise-memo caches** (see code map / gotchas below).
- **`null` = "not chosen", never "off"** (`lib/settings.ts`). Every remembered preference distinguishes an absent value from a false one, because that is the only way a default can apply *and* a choice can stay sticky: `lang: null` follows the browser, `effects: null` follows `prefers-reduced-motion`, `search: null` lets the first visit seed a filter from the language. Write `false`, and the reader is recorded as having chosen something they never touched.
- **Precompute across entries; fetch per entry only on demand.** Anything that needs a *cross-entry* view of `pages/` (the facts index) is a build-time projection served as one file (`vite/facts-digest.ts` → `lib/dossier/digest.ts`), with the per-entry crawl kept as the fallback and both ending in the same pure projection function. Anything that needs *one* entry is fetched when the reader opens it. Adding a second many-request feature is the mistake this pattern exists to prevent.

## Landmines (verify before you touch)

**CSS**
- **The stylesheet is fourteen files, and their import order in `index.css` is the cascade.** It is unlayered, so two rules of equal specificity are settled by which file was imported first. `tokens.css` must stay at the top; `chrome.css` owns `btn-rpg` and must stay above `codex.css` and `viewers.css`, which both narrow it. Reordering the import list is a behavioural change, not tidying.
- **Unlayered rules in `src/styles/*.css` beat Tailwind's layered utilities.** A hand-written `.foo { position: … }` will override `class="absolute"`. Documented scars: `.btn-rpg` must NOT set `position`; the codex scroll area relies on `absolute inset-[11px]`; `.herald` and `.search-panel` own their `position` (their `::before`/`::after` rules need it) so those elements must not carry a position utility; **`.form-ink { width: 100% }` silently swallowed `w-[4.6rem]` on the year inputs** — narrow a form field by sizing its *wrapper*, never by a `w-*` class on the input. When adding semantic CSS, don't set properties you also drive with utilities on the same element.
- 🔴 **Stacking is a *sibling* contest, and `main` must out-rank the footer** (found 2026-08-18). The refinement panel hangs out of the search bar on `position: absolute`, so with no results the short page drops it straight over the colophon — and a `z-40` **inside** `main` cannot help, because a descendant can never out-paint a sibling of its stacking-context ancestor. `main` and `SiteFooter` both sat at `z-10`, so DOM order won and the footer's decorative rule swallowed the clicks meant for "Clear refinements". `main` is now `z-20`. The whole ladder, low to high: **backdrop −10 · footer 10 · main 20 · header 30 · codex/viewers 40–70**. Before adding a z-index anywhere, place it on that ladder.
- 🔴 **`body` must stay background-less, or every `-z-10` backdrop layer vanishes** (found 2026-08-13). `Background` and `MusicalDrift` are `position: fixed; z-index: -10`, i.e. child stacking contexts with a negative stack level — and those paint at step 2 of the root's painting order, *before* the in-flow backgrounds of the root's descendants (step 3), which is where `body`'s own background lands. `html` already carries the flat paper colour, so it fills the canvas and the overscroll gutter; the moment `body` gets an opaque colour too, it covers the manuscript gradient, the grain, the vignette and the rising glyphs completely. (The usual Tailwind `-z-10` backdrop works only because preflight leaves `body` transparent — this file had set both.) If a backdrop layer "does nothing", check `body` before debugging the layer.
- **A glyph is not a size.** `--font-music` resolves to Segoe UI Symbol on Windows, Apple Symbols on macOS and Noto Music on Linux/Android, and each draws U+1D11E at a different fraction of the em — so `ClefSpinner`'s fixed `font-size: 1.45rem` rendered a clef about a fifth larger on Linux and Android than the search box was built for. Anything sized by a *system-font glyph* has this problem. The fix is to measure the ink box (`measureText`, detached canvas, no reflow) and hand CSS a size in `rem` and corrections in `em`; `TARGET_INK_REM = 1.5625` is precisely the Windows appearance, so the normalisation is a no-op where it already looked right (verified: measured back at `1.4500rem`).
- **`::: lead` is a drop cap, not a type size.** The spec only *permits* larger type ("MAY render it with larger type or a drop capital"), and `.bio-lead { font-size: 1.24rem }` made a lead's own sentences a different size from the paragraph beneath them — i.e. a block that silently switched fonts mid-article. `.bio-lead` now sets colour only and inherits `.bio-article`'s measure. Don't reintroduce a size there.
- **Reduced-motion is dual-tracked and was inconsistent.** framer uses `useReducedMotion()`; CSS uses `@media`. A CSS `@media (prefers-reduced-motion){ transform:none }` guard once silently killed the requested `.fx-curl` hover zoom for users with reduced-motion on. Decide per-effect whether it's decorative (suppress) or a functional affordance (keep), and don't blanket-disable transforms.

**Content / paths / dates**
- **Never `new Date(metadataDateString)`** — dates are `DD.MM.YYYY`. Use `parseDmy`/`formatDmy`/`yearOf`/`ageOf` (`metadata.ts`).
- **Three independent bases.** index.json + its `json`/`md`/`img` resolve via `APP_BASE`; in-entry media/documents resolve via `RESOURCE_BASE_PATH` (`VITE_RESOURCE_BASE_PATH ?? /pages`); index.json's **`pdf` resolves against the site root** via `resolveSitePath` — a leading slash and nothing else. A plain root deploy will 404 media unless `VITE_RESOURCE_BASE_PATH` points where `pages/` actually lives; `pdf` needs no configuration because the archive never moves. Do **not** put a PDF under `/pages` and then write `pdf: "pages/…"` — that is the resource base's convention, not this one.
- **Dev serves the archive by fall-through, not by prefix proxy.** `vite/legacy-archive.ts` fetches anything `publicDir` can't serve from abc-guitars.com and streams it back same-origin (local files always win). It replaced a `/pages` proxy, which could not work: a target that climbs out of the base (`^/main/x.jpg`, `/../main/x.jpg`) no longer *starts* with `/pages` by the time it is requested, so the proxy never matched and Vite answered with the SPA shell.
- **Escaping the resource base is a real feature, not a hack** (BioMD 1.4 §15.1). `^/main/x.jpg` anchors at the resource root; `/../main/x.jpg` climbs out. `resolveResourcePath` collapses `.`/`..` itself and clamps at the root, so the emitted URL is the one actually requested. Prefer `^` — `..` only works when it matches the base depth segment for segment.
- **`resolveResourcePath` swallows a leading `pages/`** (`basePrefix`, a documented back-compat shim for legacy content): `pages/photo/k/x.jpg` → `/pages/photo/k/x.jpg`, not `/pages/pages/…`. Consequence: a real directory named `pages` *inside* the base is unaddressable. Don't write the prefix in new content.
- **`publicDir = ../pages` IS the content store** — editing `../pages/**` changes served content with no rebuild; the tree also ships in `dist`.
- **json/md are localized (`/<lang>/…`), media are NOT.** Use `localizeContentPath` only for json/md.
- **`index.json` v1 deviates from the metadata spec**: free-text `country` (not ISO), no `id`. ✅ **Resolved by the v2 spec** — the index now owns `id` and ISO `country` and is the source of truth for identity. Mixed leading-slash conventions stay (`json`/`md` rooted, `img` bucket-relative). Follow [`docs/Catalog-Index.md`](../docs/Catalog-Index.md) for new content.
- **v2: `*.bio.json` is a per-language *edition*.** `forename`, `surname`, `birthplace`, `instruments`, `jobs`, … must be authored in the directory's language; only `dates`/`ranking`/`url` are invariant. The current fixtures violate this and are **not** examples to copy (Step 2 fixes them).
- **v2: `json` present ⟺ biography.** An entry without a dossier is a *page*: no tabs, header shows display name + country. Declared in `index.json`, never inferred from a failed fetch.
- **v2.1: `pdf` without `md` ⟺ document.** The row *is* a PDF: App mounts `LazyPdfModal`, not `LazyCodexModal`, and there is no article, dossier, tab, header or per-entry language menu to arrange (spec §9.1). A row carrying **both** `md` and `pdf` stays an ordinary entry — the article wins and the PDF is just an archive file it can link. `json` on a `pdf` row is meaningless; omit it.
- **Never import `pdfjs-dist` outside `lib/pdf/engine.ts` or `components/pdf/`.** It is ~415 KB gzipped-to-123 KB plus a 1.2 MB worker; the whole point of `LazyPdfViewer`/`LazyPdfModal` (and of `components/pdf/index.ts` re-exporting *only* the lazy wrappers) is that a session which never opens a PDF never downloads any of it. Check `dist/assets/index-*.js` for a static import of the `pdf-*` chunk after touching this.

**Routing / modal / focus**
- **Body scroll-lock is owned by `App`, not the modal**, and keyed on **`codexOpen` (a boolean), never on the record** — depending on the record unlocks and re-locks the body on every ← →, handing the page its scrollbar back for a commit and reflowing the grid under the modal. Don't move it into the modal and don't widen the dep.
- 🔴 **The codex modal is deliberately *unkeyed* in `App`** (fixed 2026-08-13). Keying `LazyCodexModal` on the slug made every ← → a teardown + rebuild: `AnimatePresence` held two shells at once for the 250 ms crossfade, so **two translucent backdrops stacked** — and they do not add up to one, `1-(1-0.55a)(1-0.55b)` dips to ~0.47 mid-turn, which is the reader seeing the page flash back through — plus a second full-viewport `backdrop-filter`, the 0.85 s opening turn replayed, `audio.open()` re-fired and the article refetched. The shell now persists; `CodexModal` keys the **view** (`<View key={record.slug}>`) so the new entry still lands on its Biography tab. Reset-by-remount lives one level down from where it used to.
- **Closing the codex is one movement on one clock.** `CLOSE_MS` in `CodexShell.tsx` and `.page-turn-close` in `index.css` must stay equal (0.32 s): the panel turn and the backdrop fade run *together*, and `AnimatePresence`'s `exit` is `duration: 0` because nothing is left to fade. It used to be a 450 ms turn *followed by* a 250 ms backdrop fade — 700 ms to shut a book that opens in ~500 ms, with the dim hanging on after the panel had gone. **Under `prefers-reduced-motion` `closeMs` is 0**: the blanket rule at the foot of `index.css` clamps every animation to 0.001 ms, so a fixed timer there is pure dead waiting, not a wait for movement (measured 670 ms → 17 ms).
- **`useCodexEntry` derives `contentLang` during render, never from an effect.** With the shell persisting, an effect renders one frame with the *previous* entry's edition still selected, and that frame's loader fires a request for an edition nobody asked for — often one that does not exist (`de/authors.bio.md`). It also reads `catalog.peekEntry` synchronously, so turning to an already-read entry paints in the same frame instead of flashing `CodexSkeleton`.
- **Escape ordering is capture-phase.** `LanguageMenu` and `ImageViewer` register `keydown` in the capture phase and `stopPropagation()` so Escape closes them before the codex behind them. Preserve this when adding nested overlays.
- **Hash route slugs are ASCII `[\w.-]+`** (`SLUG_PATTERN` in `lib/entry.ts`, percent-decoded) — dots allowed, so `#/goya2.right` routes. Setting `location.hash` fires `hashchange` (state updates), but the null-clear uses `history.pushState` (no event). Programmatic hash changes from outside React may not switch entries — reload to re-init.
- **One link classifier, `entryTargetSlug`** (`lib/entry.ts`) decides whether a URL is an in-app entry (`#/slug`, `/#/slug`, `x.bio.md`, `x.md`). `BioArticle`'s `a` handler is its only caller and passes the **slug** to `onNavigateEntry`; `App` only checks the slug exists. Don't add a second URL parser — extend this one.
- **A link to a slug that isn't in `index.json` does nothing** (App's `bySlug.has` guard, unchanged policy from v1). That is a *content* error and belongs to `lint:content` (Step 7), not to runtime defensiveness. `pages/ru/goya2.right.md` has several — it is a routing fixture, not reference content.
- 🔴 **`fold()` must not blanket-strip combining marks.** `normalize("NFD")` decomposes Cyrillic `й` into `и` + breve; deleting every mark turned `йовичич` into `иовичич`, so it could only transliterate to `iovicic`, never `jovicic` — a silent cross-script miss for every name with `й` (fixed 2026-07-31). The strip is now scoped to Latin bases (`/([a-z])[̀-ͯ]+/g`) followed by `normalize("NFC")`. If you touch `fold`, check `Agustín→agustin`, `Jovičić→jovicic`, `Ёлка→елка` **and** `йовичич→йовичич` together.
- **Search work is split by what it depends on.** Corpus-only work (folding, weights, the ASCII flag) belongs in `search/docs.ts`; query-only work (folding, tokenizing, transliterating) belongs in `search/scoring.ts`'s `tokenize`; criteria-only work (folding terms, parsing years) belongs in `search/criteria.ts`'s `compile`. Anything left in the per-doc loop runs `docs × fields` times per keystroke. The current budget: **0.398 ms/query at 1249 docs** — re-measure before adding an index.
- 🟠 **Dossier-backed criteria (given/family name, birth/death years) are only as complete as the crawl.** `matchesDossier` treats an unread dossier as **not matching**, so while `lib/dossier` is still reading, a name/year search is *narrower* than the truth and widens as facts arrive (`DossierProgress` says so out loud). Never invert this to "assume it matches" — a result list wider than the evidence is the worse failure. Also: `App` must keep passing `NO_FACTS` unless `compiled.needsDossier`, or every throttled batch re-runs the whole search.
- **The facts crawl is `pages/`-scale sensitive.** One `*.bio.json` per *listed* entry — 8 requests today, ~10³ at the full legacy set. It is bounded (`DOSSIER.concurrency`), idle-scheduled and cache-shared with the codex, and `whenIdle`'s `timeout: 400` guarantees progress even in a tab that never idles (that ceiling is ~10 entries/s in the worst case). If it ever needs to be cheaper, the escape hatch is a precomputed digest in `pages/` behind `factsStore`'s loader — **no caller changes**. Don't "optimize" it by making the search assume unread dossiers match.
- **The herald's clocks are absolute, its deps are lengths.** The reveal deadline is `Date.now() + delay` captured once, so a playlist rebuilt by streaming facts cannot keep postponing the first message; the rotation effect depends on `playlist.length`, not the array, so an equally long rebuild does not restart the 30 s clock. With ≤ 1 message there is deliberately **no timer at all**. If you add a message kind, keep both properties.
- **`?herald-date=DD.MM.YYYY` (DEV only) pins "today"** so an anniversary can be looked at without waiting for the calendar (`lib/herald/today.ts`). Real dates in the fixtures: `21.02` Segovia's birth, `07.08` Barrios's death, `05.05` Barrios's birth.
- **The codex is composed, not branched.** `CodexModal` (45 lines) picks `BiographyView` or `PageView` from `record.biography` and hands both to the same `CodexShell`; both build the same `CodexHeader` from different data. If you find yourself adding `if (isPage)` inside the shell or the header, the data should differ instead.

**Audio**
- **The mute (🔊) toggle silences only the procedural engine (SFX+ambient+theme)** — mp3/MIDI/tab playback live on separate contexts and keep playing. This is current behaviour, widely assumed to be a bug (see [15](15-app-critique.md)).
- **Three `AudioContext`s + one `HTMLAudioElement`, none ever `close()`d** — mobile/Safari concurrency risk; don't add a fourth casually.
- **Ambient + SFX intentionally bleed over content**; only the per-entry *theme* yields to a recording. Don't "fix" that.
- **StrictMode double-invokes effects in dev** — schedulers/unlock must be idempotent.

**Search / i18n / flags**
- **v1: the Latin slug (from the md filename) is the sole bridge letting Latin queries hit Cyrillic entries.** Keep migrated md filenames Latin/ASCII-hyphenated. There is no Latin→Cyrillic table. **v2** makes `index.json.title` the explicit Latin fallback and `index-<lang>.json` aliases the primary mechanism — the slug bridge stops being load-bearing (but the filenames stay Latin, because they are the routes).
- **CJK cannot be transliterated at all.** `CYR_TO_LAT` covers Cyrillic only, so a `zh`/`ja`/`ko` query matches nothing in v1. Aliases in `index-<lang>.json` are the fix, not a bigger table.
- **`fold` collapses `ё→е`**, which makes the `ё` transliteration entry dead — don't rely on ё-specific translit.
- ✅ **Search is ranked** (`search/scoring.ts`) and typing is kept off the render path by `useDeferredValue(criteria)` in `App`. Re-measure before adding a debounce on top.
- **Flags are hand-drawn SVG, never emoji** (Windows renders flag emoji as letters). There are **two** sets: `Flag.tsx` (by UI language) and `CountryFlag.tsx` (by ISO country). Missing coverage falls back to text.

**BioMD**
- **`:::` fences are matched before Markdown parsing and must start at column 0** — a fenced code block containing a `:::` line will be misparsed; indented `:::` is treated as prose.
- **`# ` title lines are lifted out of the body wherever they sit**, up to **two** of them (`BioDoc.titles`), including from inside an `::: align` — the wrapper is pruned if that leaves it empty, and code/verse fences are skipped. A third `#` stays body text. Who prints them is `lib/biomd/headings.ts`' single rule: **the dossier names the entry when it can, the article's `# ` line(s) when it cannot, and a line the plate already carries is never printed twice** (`isSameName`: word overlap against the shorter side, so "Агустин Барриос" matches "Агустин Барриос Мангоре"; one-letter spelling drift forgiven). Anything the plate does *not* carry the article prints itself as `.bio-title`. Consequence: **`BioArticle` takes a parsed `doc`, not `source`** — the plate has to read the titles before the article renders, so `useBioDoc` parses once in the view.
- **No `rehype-raw`** ⇒ raw HTML in BioMD is inert (intended). Adding `rehype-raw` would open an XSS hole. Note block-derived `src` (image/document) bypasses react-markdown's `urlTransform` — treat content as trusted-only.
- 🔴 **An in-document `#name` link must never become an `<a href>`** (BioMD 1.6 §19.1). The hash **is** the router (`useHashRoute` reads `#/slug`), so following `#name` sets `selectedSlug = null` and the codex closes on the reader. `BioArticle` renders it as a `<button class="bio-jump">` that calls `scrollToAnchor` — which is also why `.bio-jump` has to be given the look of a prose link *and* of a `::: nav` pill by hand. The same reasoning rules out `scroll-behavior: smooth` on `.codex-scroll` (it would also smooth the tab-switch reset) — the behaviour is chosen per call, honouring `prefers-reduced-motion`.
- **Anchor lookup is scoped to the clicked article, not `document`** — `scrollToAnchor` resolves inside the `.bio-article` the click came from. This mattered when a ← → turn kept two codices mounted together; it still does, because the same article can be reached from a keyed view swap and because two articles are one `::: nav` embed away from coexisting. Keep it scoped; a bare `getElementById` invites landing in the wrong document.
- **A bare ``` fence is verse, not code** (1.6 §3.9): `remarkVerse` rewrites it into `.bio-verse` paragraphs with `<br>` lineation, so it wraps instead of overflowing. It runs **last** in `REMARK_PLUGINS` so fenced text stays literal. A fence *with* a language stays a `<pre>` — hence `.bio-article pre` keeps `overflow-x: auto`, the same containment contract as a wide table.

**Grid & scale** *(added 2026-08-28 — measured at 736 entries)*
- 🔴 **Never put framer's `layout` on a grid cell, and never wrap the grid in `AnimatePresence`.** Both were there, and at 736 entries the **first keystroke in the search box took 15.7 s** to reach the next frame (53 long tasks, worst 879 ms, 20 170 DOM nodes, 100 MB heap). `layout` measures every cell on every frame of a reflow and `mode="popLayout"` exit-animates each removed one; `memo` cuts re-render cost, not that. A cell now fades in **once, on mount**, and nothing animates on removal. After: 49 ms, zero long tasks.
- **The grid is paged, and the page count resets *during render*.** `CharacterGrid` compares the `records` identity it last saw and calls `setShown` in the render body (React's documented adjust-state-during-render idiom) rather than in an effect — an effect would paint one frame of the previous page count against the new results. If you add a reason for the list to change identity, this is what keeps it honest.
- **`content-visibility: auto` is scoped to `(hover: none)` on purpose.** It implies paint containment, which clips to the cell — and the card's hover lift, 4.5 % grow and 34 px glow ring all paint *outside* it. Applying it on a fine pointer would silently amputate the ornament. Layout containment (`contain: layout style`) is unconditional and safe.
- **`CharacterCard` picks its shell from a module-level `FINE_POINTER` constant**, not a hook or a prop — swapping `TiltShell` for `PlainShell` changes the hook order, so the decision has to be made once per session, above the component. The tilt's cursor glare reaches the card body as the `--card-glare` custom property (framer sets MotionValues on custom properties), which is what lets the touch shell simply not set it: the body falls back to `var(--card-glare, transparent)`.

**Dev server**
- 🔴 **`publicDir` is `../pages` — ~16 000 files — and a transient file in it used to kill the dev server.** Any tool writing a `.tmp` there (an atomic save, an archiver, a scanner) gives chokidar a file the OS then refuses to open; it re-emits `EBUSY` as `'error'`, and an unhandled `'error'` event is a process-wide crash. `vite/content-watch.ts` fixes it twice over: an `'error'` listener on `server.watcher` (the guard that actually matters — an ignore list can always miss a path) and `ignoreContent()`, which keeps the per-language content directories and every scratch-file shape out of the watch. The catalogue indexes at the root of `pages/` stay watched, so editing `index.json` still reloads.

**App-wide**
- ✅ **Two error boundaries exist (2026-08-04)** — `components/ErrorBoundary.tsx`, a class (hooks cannot catch). Placement is deliberate: one under `I18nProvider` in `main.tsx` wrapping **both viewer providers**, because they mount their overlays as *siblings* of `children`, so a boundary around `<App />` alone would not catch a throw from the image/ascii-tab viewer; one around the codex's `Suspense` in `App.tsx`, so a codex that will not open costs that entry and not the grid. Fallbacks reuse App's `loadError` voice (`font-display text-xl text-burgundy-600` + `.btn-rpg`) and the `app.crash`/`app.crashReload`/`app.crashCodex` keys. Logging is DEV-only (`import.meta.env.DEV`, `warnDev` style) — verified absent from the prod bundle.
- 🔴 **Never re-arm the codex boundary with `key`.** It takes `resetKey={selectedSlug}` (a prop compared in `componentDidUpdate`) precisely because keying the boundary would remount the `Suspense`/`AnimatePresence` beneath it and kill the ← → page-turn animation. Without any re-arm, one entry with unrenderable content would keep every later entry shut.
- **A rejected `lazy()` import is permanent for the life of the page** — `pending ??=` caches the rejected promise *and* React caches the rejected payload, so no retry can ever succeed. That is why both fallbacks offer a **reload**, not a retry. This is a production failure mode, not just a dev one: the classic trigger is a deploy replacing hashed chunk filenames under an already-open tab (verified against `dist` with the codex chunk deleted), the second is a dropped request on a phone.

- **Add a UI language:** (1) add to `LANGUAGES` in `languages.ts` (order is curated, not alphabetical); (2) create `lib/messages/<code>.ts` typed `Record<MsgKey,Message>` with ALL keys; (3) add it to `DICTS` in `messages/index.ts`; (4) draw the flag in `Flag.tsx` (`FLAGS` is `Record<Lang,…>` → compile error if missing). `Intl.PluralRules`/`DisplayNames` handle locale formatting.

Do **not** call `localStorage` from a feature module — `i18n.tsx` and `fx/store.ts` were converted away from exactly that, and they keep their own domain rules (what a valid language is, what reduced motion implies) while `settings.ts` owns only storage.
- **Add a country to the catalogue:** `index.json` takes lowercase ISO alpha-2, and `components/CountryFlag.tsx` needs a matching entry in `COUNTRY_FLAGS` — the country facet is a **row of flags** now, so a missing one degrades to bare ISO letters (`hasCountryFlag()` is the guard). The `H2`/`H3`/`V3`/`Nordic` helpers cover most designs; emblem-bearing flags are drawn simplified on purpose, since at 24×16 on parchment the band scheme is all the eye reads.
- **Change how many cards the grid shows:** `GRID` in `config.ts` — `pageSize` (first paint and after every filter change), `pageStep`, `autoPages` (free scroll-reveals before the reader must click) and `revealMargin`. Nothing else needs to know.
- **Add a search criterion:** three edits. (1) a field on `SearchCriteria` + its default in `EMPTY_CRITERIA` + one line in `refinementCount` (`lib/search/criteria.ts`); (2) parse/fold it in `compile` — and set `needsDossier` if it can only be answered from a `*.bio.json`; (3) one clause in `matchesIndex` **or** `matchesDossier` (`predicates.ts`). - **Add / retune a decorative effect:** ornaments are budgeted, never unconditional. (1) a switch + any ceiling on `EFFECTS` in `src/config.ts`; (2) if it has a cost worth grading, a row in `DENSITY` in `lib/fx/store.ts` (per-`PerfTier` — not an `if`) and a field on `FxSnapshot`; (3) the component reads `useFx()` and returns `null` when its budget is 0, so a disabled effect costs no DOM. Animate **`transform` and `opacity` only**, and keep keyframe values **literal** — a `var()` inside an animated `transform` can drop the animation off the compositor in some engines, which is exactly the device class the budget exists to protect (that is why `fx-rise-0…2` are three near-identical keyframe sets instead of one parameterised one). `EFFECTS.tier` pins a grade so a weaker device can be seen without owning one.
- **`MusicalDrift`'s three `STEPS` are one R₃ set (powers of 1/φ₃), not three loose constants.** They place every glyph, so mixing families breaks *coverage*, not just variety: seeding the horizontal channel from the **2D** plastic set (1/ρ = 0.7548776662) left the right **17.7%** of every viewport permanently empty at 18 glyphs, and **23.5%** at 5 — so phones and weak machines got the worst of it, and it read as the effect stopping short of the right edge. Retuning these is a measurement: check the largest uncovered band at n = 5…24 *and* the cross-channel correlation (the golden ratio covers well but correlates −0.31 with the size channel, which drifts big glyphs to one side). Fixed 2026-08-13.
- 🔴 **Never let a capability grade switch an effect off, and never fold `prefers-reduced-motion` into one** (both shipped wrong on 2026-08-13, fixed same day). Folding them made a 32-core machine report `low`, which zeroed *every* ornament — and because `low` zeroed them at both switch positions, the reader's on/off button changed nothing while still claiming "on". Keep three axes apart: the grade scales **quantity**, the reader's switch is the only thing that turns an effect **off**, and the OS hint only picks that switch's **default** (`EFFECTS.respectReducedMotion`). Corollary: `index.css`'s blanket `@media (prefers-reduced-motion)` rule clamps `animation-duration` with `!important` on `*`, so an opted-in ornament needs the paired `html[data-fx="on"]` rule at the foot of the file to win it back — which is also why per-glyph durations travel as the `--fx-dur` custom property (a plain `animation-duration` cannot be handed back). `App` writes `data-fx`. When an effect "does nothing", read `window.__fx.state` in DEV before reading code.
